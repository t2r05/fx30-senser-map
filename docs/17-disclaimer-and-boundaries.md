## 二、硬件风险（最重要）

固件逆向与设备修改存在**变砖风险**，可能使设备**失去保修**。

| 风险 | 说明 |
|---|---|
| **变砖** | 部分命令（`0x4003` FORMAT / `0x4006` FIRMUP / 写设置区）可能让相机无法启动 |
| **失去保修** | 任何非官方写入都可能触发售后拒保 |
| **数据丢失** | 写设置区、格式化分区会覆盖原厂数据 |
| **不可逆** | 已写入的固件区通常无法自行恢复 |

**操作守则：**

1. 只在**自有设备**上操作，理解全部风险后再开始。
2. **出错时先停止，不要盲目重试写入** —— 重复写入会把「一次可恢复的错误」变成「不可恢复的错误」。
3. 任何写操作前，**先完整备份**对应区域并验证备份可读。
4. 拍摄模式下另备一张**空卡**，避免测试写入损坏正在使用的存储卡。
5. 电池电量不低于 50%，全程 USB 稳定供电。

## 三、本仓库的脚本分级（务必先看）

> ⚠️ **早期版本的 `tools/README.md` 声称「全部只读」，这是不准确的。**
> 实际存在**写入型**脚本。已在本页与 `tools/README.md` 中更正。

| 级别 | 含义 | 脚本 |
|---|---|---|
| 🟢 **纯静态分析** | 不接触相机，只读本地固件镜像 | `tools/offline/` 全部、`tools/payload/check_so.py` |
| 🔵 **只读探针** | 只向相机发送**读**请求，不改相机任何状态 | `probe_sony.ps1` / `scsi_probe.py` / `extcmd_probe.py` / `pmca_extcmd_check.py` / `senser_auth.py` / `jiritsu_probe.py` / `jiritsu_deep.py` / `jiritsu_deep2.py` / `jiritsu_pdt.py` / `probe_603_ns.py` / `mem_probe.py` / `term_probe.py` |
| 🟡 **含写操作（需显式参数才触发）** | **默认只读**，只有传入特定参数才写相机 | `probe_fileid_map.py`（`--delete <file_id>` 发 `0x4009`/`0x4012` 删除 + `0x4002` 重挂；`--mount` 发 `0x4002` 重挂） |
| 🟡 **含写操作（每次运行都写）** | **默认就会写相机的设置区**，写入前自动存完整快照 | `probe_drive_write.py`（写驱动模式：`0x8EF80` + `0x91690` 成对写入，回滚材料存于 `dump/drive_before.bin`） |
| 🔴 **构建型（不接触相机）** | 只在主机上生成/校验 `.so` 载荷字节码，**不含下发脚本** | `tools/payload/build_payload.sh` |

> 🟡 `probe_drive_write.py` 会改变相机的**拍摄模式**（可开启隐藏连拍模式）。
> 每次运行前自动落一份完整回滚快照（`dump/drive_before.bin`），
> 回滚命令：`python tools/probe_drive_write.py 0x8EF80=0x00 0x91690=0x00`。
> **验证写操作必须拔电池 ≥30 秒做冷启动** —— 关机再开机是热重启，走
> `nflasha5` 暖启动镜像恢复路径，会把改动吃掉。

**明确不含**（有意不提供）：

- ❌ 直接下发载荷到相机的脚本
- ❌ 固件写入 / 刷写脚本
- ❌ 绕过授权检查的密钥或证书
- ❌ 任何固件二进制或备份数据文件
- ❌ 写入固件分区（`nflasha*`）的脚本 —— 所有写操作只限于 `/setting` 设置区

## 四、危险命令清单（已知会出事）

| 命令 | 名称 | 后果 |
|---|---|---|
| `0x4003` | FORMAT | 同族平台实测**卡死服务**，勿发 |
| `0x4006` | FIRMUP | 同族平台实测**卡死服务**，勿发 |
| `0x60F` 区间 | — | 会使端点进入异常状态，应回避 |
| `0x603/4` 全量写 + `0x603/3` 提交 | 设置区写回 | **必须先留完整原始快照**；备份区写坏可能影响启动，该层风险**未评估** |
| `0xff01` FileControl | — | FX30 上全部返回 128（错误码语义，非「不支持」） |

## 五、已知踩坑（避免重复劳动）

| 症状 | 真实原因 |
|---|---|
| MSC 查询后认证失败 | 同一 USB 句柄先做 SCSI（`getDeviceInfo`/`getCameraInfo`）再发认证，bulk 端点状态被污染。**查询与认证必须用不同句柄**，查询句柄用完即 dispose |
| 认证后等不到 `054C:0336` | 重枚举需要时间。窗口建议 **25 秒**（0.5 s 轮询）；本仓库脚本用 20 秒，实测够用 |
| 相机屏幕显示「请检查所连接的设备」、电脑不出现盘符 | 正常现象，以脚本日志为准 |
| macOS 认不出设备 | 内核驱动占用接口，必须先 `detach_kernel_driver(0)` |
| `0x4009` 删除后返回 130 | `130` = **nflasha6 已卸载**，不是「文件不存在」。必须再发 `0x4002`(MOUNT) 重挂 |
| 端点莫名超时 / 结果不可信 | 之前发过未知 pFunc 打崩了端点。**之后所有结果一律不可信，必须重开会话** |
