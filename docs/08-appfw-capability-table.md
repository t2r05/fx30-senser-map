# 08 · appFw.so 机型能力表：结构与差分结果

>
> **本文 §5 认定的「能力表」极可能是假阳性，§6 的 16 个连拍补丁偏移已失去依据，请勿刷写。**
>
> 撤回理由（用修正后的 xref 扫描器复核）：
>
> | 检查项 | 结果 |
> |---|---|
> | `.text` 中 `adrp+add` 指向该区间 | **0 处** |
> | `.text` 中 `adrp+ldr/str` 指向该区间 | **0 处**（此前扫描器漏检此类，共 144,690 处） |
> | 939,407 条重定位中 addend 落在该区间 | **0 处** |
> | 全文件 u64 指向该区间 | **0 处** |
> | 代码实际访问的 `.data.rel.ro` 页 | 仅 `0x419`–`0x41C` 四页，该表所在页从未被访问 |
> | A6700 同类表（已知 FTP 偏移所在处） | 同样 **0 引用** |
>
> 也就是说：那 123KB 数据**不被任何代码或指针引用**，大概率只是恰好符合
> `{u32 0/1, u32 递增 ID}` 特征的普通数据。当时仅凭「8 字节步长 + 0/1 比例 40% + 220 周期」
> 就判定为能力表，**证据不足**。
>
> **仍然成立的部分**：功能 ID 编号体系是真的（`idx=419 = DRIVE_MODE_CONT_SHOOTING`，
> 连拍四档 HI_PLUS/HI/MID/LOW 位于 va `0x4134AD8` 的 idx 45–48），这部分有完整字符串证据。
>
> 另外补充一条独立结论：**FX30 与 FX3 是不同构建**，22 点采样只有 14% 逐字节命中，
> 二者不能做字节级差分（此前"只差 16KB 所以可差分"的思路不成立）。
>
> 完整分析见项目内 `fx30_hack/ANALYSIS-part2-appFw.md`。

## 一、为什么做三机型差分

早期只有 FX30 一台固件，无法判断某个字节是「FX30 被禁用」还是「所有机型都这样」。引入：

- **A6700 2.00**：有连拍，且 Powerful6700 的 `FEATURES.md` 已公开解锁偏移，可作**已知答案的校准尺**；
- **FX3**：同 Cinema Line、同为 BIONZ XR，有连拍 —— 最接近 FX30 的对照组。

三台 `appFw.so` 体积：A6700 `89,027,992` / FX30 `79,032,104` / FX3 `79,015,712` 字节。
**FX30 与 FX3 只差 16,392 字节（0.02%）**，但这不是简单的数据差异——`.text` 本身相差 11,128 字节。

## 二、字节级 diff 为什么不可用

| 段 | 结论 |
|---|---|
| `.text` / `.data.rel.ro` | 公共前缀 = 0（函数与数据整体位移，重定位指针全变） |
| `.data` | 尺寸相同，但 463,230 字节不同，绝大多数是重定位噪声 |
| `.rodata` | 公共前缀 60%，但关键表在差异段内 |

→ 必须换成**结构化定位**：按数据结构的形状找表，而不是按偏移。

## 三、能力表结构（已确认）

以 A6700 公开偏移 `0x3f17524` 为锚点，确认结构为：

```
8 字节/项: { u32 supported, u32 feature_id }
            00 = 禁用 / 01 = 支持
```

表位于 `.rodata`，规模：

| 机型 | 表偏移 | 项数 | 1 占比 |
|---|---|---|---|
| A6700 | `0x3EF69B4` | 17,236 | 39.7% |
| FX30 | `0x37C2C8C` | 15,466 | 40.3% |
| FX3 | `0x37BFF64` | 15,452 | 41.3% |

### 行宽 220

同一 `feature_id` 每隔 **220 项**重复出现一次 → 表是 **二维矩阵：行 = 变体，列 = 功能**。
FX30 共 71 行（70 整行 + 余项），每行 220 列。

## 四、feature_id → 功能名

`.data.rel.ro` 中存在功能名指针数组（FX30 表头 `0x4120288`，941 项），下标即 `feature_id`：

|---|---|
| 418 | `DRIVE_MODE_1_IMAGE_SHOOTING`（单张） |

## 五、核心结果（含关键负结果）

### 5.1 id=419（连拍）在 FX30 与 FX3 中**完全相同**

| | 0 的槽 | 1 的槽 |
|---|---|---|
| FX30 | 16 | 62 |
| FX3 | 16 | 62 |
| 0 所在行 | `0,1,2,4,5,6,7,8,27,28,29,31,32,33,34,35` | 两台**完全一致** |

**结论：FX30 与 FX3 的能力表在连拍这一项上没有任何差异。** 这张表**不是**直接的开关。

### 5.2 由此推出的真正机制

FX3 能用连拍，不是表值不同，而应是**运行时选中的行不同**：表内既有 `419=1` 的行，也有 `419=0` 的行；机型决定读哪一行。FX30 很可能被映射到 `419=0` 的行（0–8 或 27–35 之一）。
