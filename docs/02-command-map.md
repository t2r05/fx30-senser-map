# `pFunc=0x40` 命令空间图谱

在 **ILME-FX30 Ver.6.00** 上，对 `AdjustControl`（`pFunc=0x40`）命令空间做的系统扫描结果。

请求格式：`12 字节小端头 (size:32, pFunc:16, sequence:16, 4×8bit) + CommandHeader(category:16, command:16) + payload`

> `sequence` 从 `1` 开始逐请求递增，**不可跨会话复用**。

---

## 响应码语义

实测归纳（在 FX30 上稳定复现）：

| res | 含义 | 判据 |
|---|---|---|
| `0` | 成功 | 有返回数据或返回空 |
| `128` | **命令不存在 / 该接口未实现** | FileControl、MemoryDump 全部返回此值 |
| `129` | **命令存在，参数缺失或格式不符** | 0x603 cmd1/2 空 payload 与多种 payload 均返回此值 |
| `130` | 命令存在但被拒绝（状态不符） | 成段出现（0x602/0x605/0x607） |
| `192` | 命令存在但被拒绝（另一类） | 成段出现（0x606/0x609–0x60E） |

**注意**：`128` 与 `129` 的区分是本次测绘最有用的工具——它让我们能在**不破坏设备**的前提下区分「接口不存在」与「命令存在但用法不对」。

## 命中命令的返回值特征

### `0x604`（PMCA 未定义此类）

三次重复调用，返回值完全不变 → **常量**，非动态数据：

| cmd | 值 | 推测 |
|---|---|---|
| `0x01` | `00` | 状态/开关 |
| `0x02` | `00 46 00 07` | 版本号形态（0x0046 / 0x0007） |
| `0x03` | `00 01` | 计数或模式 |

### `0x610`

| cmd | 值 |
|---|---|
| `0x01` | `00` |
| `0x02` | `02 00 00 00` |

### `0x611 cmd1` — 事件日志（2,097,220 字节）

结构：**4 字节头 + 131,076 条 × 16 字节记录**（`131076 × 16 + 4 = 2097220`，整除）

记录按 4×u32 小端拆解：

| 字段 | 观测 | 判定 |
|---|---|---|
| field0 | `0x8880000A` / `0x8880000F` … 低位递增 | 事件类型编号 |
| field1 | `0x67286594` / `0x6728A849` … 逐条递增 | **Unix 时间戳**（2024-11 前后） |
| field2 | `2` / `0x0A` … | 参数或计数 |
| field3 | 多为 `0` | 保留 |

**131,076 条中 115,729 条 field0 = `0xFFFFFFFF`（空槽）**，有效记录约 15,347 条 → 预分配环形日志。

### `0x603 cmd5` — 完整备份（2,253,564 字节）

见 [`03-backup.md`](03-backup.md)。

## 未覆盖区域

- `cmd > 16`（未扫）
- `category < 0x600`、`0x630–0x6FF`（未扫）
- 其他 pFunc（`0x20` FirmwareUpdate、`0x30` MiconAccess、`0xff00` TestMode、`0xff02` Sonar）——**均未测试**，其中 `0xff00`/`0xff02` 值得后续验证

## 复现方法

见 [`tools/`](../tools/)：

- `jiritsu_probe.py` — 阶段 A 验证通道活性 + 可选扫描（`--scan`）
- `jiritsu_deep.py` — 0x604 特征化 + 0x603 多 payload 试探 + 0x610 段补扫
- `jiritsu_deep2.py` — `cmd 4–16` × 命中类别 + `0x620–0x62F`
- `jiritsu_pdt.py` — 备份数据落盘

所有脚本**只发读请求**，结束时发 `StopSenser` 干净退出。
